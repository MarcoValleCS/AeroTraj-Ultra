# Documentation

Five documents, each with one job.  Read the guide first; the rest are references.

| document | role | read it when |
|---|---|---|
| [`GUIDE.md`](GUIDE.md) | **the project manual** — the problem, the data, the pipeline, the environment, the conventions, the troubleshooting, the repository map | you are new to the repository, or you need to run something |
| [`PAPER.md`](PAPER.md) | **the technical report** — the method, the experiments, the results, the ablations, the latency, the negative results, the limitations | you want the evidence and the numbers |
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | **the formal specification** of the model, equation by equation | you want to re-implement the model, or to check a detail |
| [`MODELS.md`](MODELS.md) | **the catalogue** of every implemented model, with its source and its conformance report | you want to know what a model is, where it comes from, and whether it is faithful |
| [`EXPERIMENTS.md`](EXPERIMENTS.md) | **the lab notebook** (Italian), chronological — every run, every number, every bug | you want the history of a result |

Supporting material:

| file | content |
|---|---|
| [`figures/README.md`](figures/README.md) | the figures, the three ways they are produced, how to rebuild them |
| `../README.md` | the front page: the headline results, the quick start, the citations |
| `../results*/` | the machine-readable artefacts of every run (JSON, CSV, markdown) |
| `../test_conformance.py` | the executable form of `MODELS.md` §3 |

## Suggested reading order

1. `../README.md` — the headline numbers, in two minutes.
2. `GUIDE.md` §1–§5 — what the problem is, how the code is organised, what the data is.
3. `PAPER.md` §1, §4, §6 — the method and the evidence.
4. `MODELS.md` — the catalogue, if you care about the baselines.
5. `ARCHITECTURE.md` — the equations, if you want to rebuild the model.

## Conventions of these documents

* **Every number in the prose comes from a file in `results*/`.**  The tables are
  generated by `make_table_mae_rmse.py` and `make_bench_10s_report.py`, not typed by hand.
* **Deviations are declared, not hidden.**  When an implementation departs from its source,
  `MODELS.md` says so and gives the reason and the measured consequence.
* **Negative results are part of the results.**  `PAPER.md` §9.2 and `EXPERIMENTS.md` record
  what did not work, with the diagnosis.
* `check_docs.py` verifies that the cross-references, the tables and the file names in these
  documents match the repository.
